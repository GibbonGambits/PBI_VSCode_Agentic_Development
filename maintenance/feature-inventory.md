# Feature inventory

This is the template's list of native Power BI features, one row per feature, with what Microsoft says about each and how far this template covers it. It is a working paper for the template's maintainer; GitHub Copilot does not read this folder when it works on a report.

- **Date:** 11 November 2026; the "Covered here?" column was checked again against the repository later that day.
- **Sources:**
  - Microsoft Learn's Power BI documentation (the create-reports, transform-model, connect-data, developer, explore-reports and collaborate-share tables of contents, plus Direct Lake, security, Git, deployment pipeline, DAX and Power Query feature pages).
  - Microsoft's release notes from November 2024 to November 2026, as far as they could be read: the Learn update archive and the current "What's new" page. Not read: every monthly blog "Feature Summary" post (the blog sites refused the requests), so November 2024 to June 2025 rest on the short bullet lists of the archive. December 2024 and December 2025 have no entry in the archive. The November 2026 update was not yet published on 11 November 2026.
  - Microsoft's report and semantic model schemas (the `json-schemas` repository at commit 235796d8; newest copies in `scripts/schemas`).
  - Microsoft's TMDL pages and its Tabular Object Model (TOM) class pages.
- **Status words:**
  - **GA**: Microsoft says "generally available" on the feature page or in a release note.
  - **GA\***: the current Learn page has no preview, retirement or deprecation label. Microsoft does not use the word GA for it.
  - **Preview**: the page or a release note marks it as preview.
  - **Retiring** or **Deprecated**: Microsoft announces its removal (date given where stated).
- **Version it needs:** the release month in which the release notes list the feature, or the schema version or model compatibility level that holds it. "not stated" means no source gave one.
- **Short forms in the tables:** `L:` stands for `https://learn.microsoft.com/en-us/`. ARC is the Learn update archive (`L:power-bi/fundamentals/desktop-latest-update-archive`); WN is the current What's new page (`L:power-bi/fundamentals/whats-new`). TOM names a Tabular Object Model class page. "Not built" refers to the list of that name in `tests/fixtures/examples/INDEX.md`.
- **Standard files named in the tables** (with the finding codes of `scripts/check_project.py` in brackets):
  - `report-standard.md`, `layout-standard.md`, `pages-and-visuals.md`, `theme.md`, `desktop-bridge.md`, `visual-features.md`: in `.github/skills/pbi-report/references/`.
  - `model-standard.md`, `relationships-and-dates.md`, `dax-standard.md`, `storage-and-security.md`, `model-objects.md`, `tmdl.md`, `descriptions.md`, `data-facts.md`, `more-model-features.md`, `multiple-languages.md`: in `.github/skills/pbi-semantic-model/references/`.
  - `pbir.instructions.md` and `tmdl.instructions.md`: in `.github/instructions/`. `copilot-instructions.md`: `.github/copilot-instructions.md`. "pbi-report SKILL.md": `.github/skills/pbi-report/SKILL.md`. `check_project.py`: `scripts/check_project.py`.
- **Examples** are named exactly as `tests/fixtures/examples/INDEX.md` names them.
- **Covered here?** "yes" means guidance, a shipped example, and a check wherever the files can show a breach. "no" says what is missing. "not adopted" says why the template does not use the feature. "outside this template" marks a feature in the files that the guidance leaves to Power BI Desktop, because no Microsoft source gives its file form, or because it runs code outside the project; the reason is given.
- **How to refresh this file:** run the routine in `scripts/refresh_sources.py` (its docstring gives the steps: `check`, then `schemas` and `dax-index`, then the tests). Then read the latest monthly entry of the update archive and the What's new page, add a row for each new feature, update status and version for rows that changed, and mark covered or not covered against the standards, the examples index and the finding codes. Change nothing in the template from this file alone: a gap becomes guidance, an example and a check in the usual way.

## 6. A project from nothing, and the theme

**What Microsoft's documentation says.**

- Project files may be generated by programs: Learn lists "Programmatic generation and editing item definitions" as supported, says PBIR "supports modifications from non-Power BI applications", and says model "Write operations are fully supported".
- Required files: a report needs `definition.pbir` and either `definition/` (PBIR) or a legacy `report.json`; inside `definition/` Learn marks `version.json`, `report.json`, `pages/`, one `page.json` per page and one `visual.json` per visual folder as required. `pages.json` is optional on Learn but required by the schema repository's structure file. A model needs `definition.pbism` and a `definition/` folder with at least one `.tmdl` file (or `model.bim`). The structure file also asks for `.pbi/editorSettings.json`, which its own schema calls optional.
- If required files are deleted, Power BI Desktop recreates them when it saves the project.
- Microsoft states no minimal file list, and does not document a project built from nothing as a supported path. It warns that outside changes "can cause unexpected errors". Files must be UTF-8 without a byte-order mark; Desktop writes CRLF line endings; paths stay under 260 characters; page and visual names use word characters or hyphens.
- Custom themes: Learn supports authoring a theme outside Desktop with the public schema, but "Edits to RegisteredResources files are only supported for already loaded resources", and every resource file needs an entry in `report.json`. Changing a theme Desktop registered is supported; registering a new theme by writing the entries by hand is not described as supported, although the schema allows the entries.

**The template's decision.**

- `scripts/scaffold.py project <Name>` makes a new project by copying the shipped starter (`tests/fixtures/examples/starter`): `<Name>.pbip`, a PBIR report with one empty page, and a TMDL model holding the table `_Measures`. It refuses when the folder already holds a project.
- The theme is **not** registered by default. Microsoft Learn supports edits under `RegisteredResources` only for resources Power BI Desktop registered itself, so the developer imports `theme/theme.json` once in Desktop (Design ribbon, Import theme). Until then the check gives T001.
- `--register-theme` writes the `customTheme` entry, the resource package entry and the theme file, the way Microsoft's own report skill does. It is outside what Learn calls supported, so it runs only after the developer's yes.
- Microsoft's command-line report validator also expects a theme's inner `name` to equal its file name. The owner's theme does not: its inner name is `VisualizationScheme`, its file `theme.json`, and the owner's theme may not be changed. The validator reported the same mismatch for the starter's placeholder theme.

## 7. Fabric Git sync and deployment pipelines

Nothing was connected, synced or deployed: this section is read from Microsoft's documentation only.

**The layout in question.** The repository root holds `<Name>.pbip`, `<Name>.Report/` and `<Name>.SemanticModel/`, beside `.github`, `scripts`, `docs`, `tests`, `maintenance`, `checklist`, `theme` and `evals`.

**Verdict for Git sync: it works, with conditions.**

- A workspace connects to one Git folder of a branch. Left blank, the folder is the branch root.
- Fabric treats a folder as an item only when it is named `<display name>.<type>` and holds a `.platform` file (or the two legacy files). `<Name>.Report/` and `<Name>.SemanticModel/` qualify once Desktop has written their `.platform`; this template never writes one by hand.
- Files outside item folders are left alone: "Unrelated files not in an item folder aren't deleted", and unsupported items are ignored. So `.github`, `scripts`, `docs`, `tests`, `maintenance`, `checklist`, `theme`, `evals` and the root `.pbip` survive a commit from the workspace. Git sync never writes a `.pbip`.
- Files **inside** an item folder that are not part of the item definition are deleted on a commit from the workspace. Never keep notes or extra files in `<Name>.Report/` or `<Name>.SemanticModel/`. Empty folders are deleted too.
- The example projects under `tests/fixtures` have no `.platform` file, so by Microsoft's troubleshooting rule they are plain subfolders, not items. If one ever gained a `.platform`, a workspace connected at the root would import it as an item into a workspace folder of the same path (folders are mirrored up to 10 levels).
- Microsoft's advice for a repository that also holds workflow files and scripts is to give the workspace its own Git folder (for example `/workspace`), so item definitions stay apart from other files. With this template's layout the root works, but a dedicated folder is the cleaner choice; `more-model-features.md` rule 25 now gives this advice (row I1).
- Limits: 1,000 items per workspace; full path at most 250 characters; a file at most 25 MB; folder depth 10; commit size limits depend on the Git provider; sensitivity labels and sovereign clouds are not supported. The service writes LF line endings, Desktop CRLF.
- Formats in the service: report definitions default to PBIR and models to TMDL; Learn calls PBIP and PBIR generally available. The Git integration page still marks the Report and Semantic model items as preview.

**Verdict for deployment pipelines: unclear for PBIR reports.**

- Pipelines copy items between workspaces (stages). They do not read a repository; the repository matters only through a Git-connected workspace.
- They list Report and Semantic model as supported items, both marked preview, and models without enhanced metadata are unsupported since 12 February 2026.
- They do not copy data, permissions, role members, refresh schedules or credentials; an incremental refresh policy is copied. At most 300 items per deployment.
- Microsoft's pages contradict each other: the deployment process page says "PBIR reports aren't supported", while the July 2025 release note lists PBIR as deployable through pipelines and PBIR is now the default format.

**Other contradictions between Microsoft pages.**

- The source code format page still lists a report folder as `definition.pbir` plus `report.json`, which predates PBIR.
- The `.platform` `$schema` address in Learn's example differs from the path in the schema repository.
- The reload-preview page says `definition.pbir` cannot be edited; the REST definition page says a report is rebound "by updating this file".
